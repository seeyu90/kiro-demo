# 戰情室視覺 QA

RSpec 和 `curl` 只能證明「HTML 裡有那段字」，證明不了「使用者看到的版面是對的」。這個 skill 的
目的就是補上那一段：實際把頁面畫出來，用眼睛（截圖）和量測（元素座標）確認版面沒壞。

**這個 skill 只回報問題，不改任何檔案。** 修不修、怎麼修由使用者決定 —— 視覺問題常常牽涉
取捨（截斷 vs 換行 vs 縮字），自己動手改容易改成使用者不要的樣子。

## 前置作業

1. **確認 server 在跑。** 專案在 `warroom-data-api-prototype/`，從那個目錄啟動：

   ```bash
   RAILS_ENV=development bin/rails server -p 3002 -b 127.0.0.1
   ```

   頁面會去讀真實 Google 試算表，第一次載入每頁要幾秒到幾十秒，逾時設寬一點（90 秒）。
   如果回 500 且訊息提到找不到憑證，代表這個 worktree 缺 `config/credentials/development.key`，
   從主 checkout 複製過來即可（見 `warroom-data-api-prototype/README.md`）。

2. **確認 Playwright MCP 可用。** 工具名稱是 `mcp__playwright__*`。如果工具清單裡沒有，先告訴
   使用者「Playwright MCP 尚未載入，需要重開工作階段」，不要改用其他方式硬做。

## 檢查範圍

沒有特別指定時，檢查 Rails 應用的全部六頁：

| 路由 | 頁面 |
| --- | --- |
| `/` | 入口頁 |
| `/dashboard` | 305 專案任務進度 |
| `/issues` | 306 臭蟲議題 |
| `/burndown` | 307 人時燃盡追蹤 |
| `/project_history` | 專案歷程 |
| `/project_phase_tracking` | 專案階段追蹤 |
| `/executive_summary` | 專案週報 |

`docs/` 底下還有一套靜態展示站（純 HTML/CSS/JS，`python3 -m http.server 8123 --directory docs`），
只有在使用者改到 `docs/` 或明講要檢查它時才納入。

使用者如果只改了一頁，就以那一頁為主，另外抽驗一到兩個共用同一套 CSS 的頁面 —— 樣式是全站
共用的，改 A 頁弄壞 B 頁是這個專案最常見的迴歸。

## 螢幕寬度

每頁至少跑這三種，對應 `application.css` 裡真正存在的斷點（768px、480px）：

- **桌機 1440×900** —— 主要使用情境
- **平板 768×1024** —— 剛好落在斷點上，最容易出事
- **手機 390×844** —— 表格會切換成橫向捲動

## 要檢查什麼

### 1. 欄位對齊

這個專案每個專案區塊各自是一個獨立 `<table>`，如果沒有固定欄寬，每張表會依自己的資料算出
不同欄寬，跨區塊看過去就會歪掉。**不要只用肉眼看截圖**，量出來比較可靠：抓同一欄在不同表格
裡的 `getBoundingClientRect().left`，差超過 1px 就是沒對齊。

### 2. 文字溢出與斷行

- 短字串被擠成直向斷行（「功能」拆成上下兩行、「2026-09-17」斷成兩段）
- 長字串撐破容器或被裁掉（PR 標題動輒一整句話）
- 檢查方式：比對元素的 `scrollWidth` 與 `clientWidth`，以及 `getBoundingClientRect()` 有沒有
  超出父容器

### 3. 深淺兩色主題

預設是**淺色**；深色要靠 `<html data-theme="dark">` 啟用。兩種主題都要截圖，重點看：

- 有沒有元素在某一個主題下對比不足（例如淺色背景配淺色文字）
- 有沒有硬寫死的顏色沒跟著主題換（專案階段追蹤甘特圖的 `--gantt-stage-*` 是**刻意**不隨主題
  變的，那是正常的，不要報成問題）

### 4. Turbo 換頁後互動是否還活著

這是這個專案踩過的坑，每次都要驗：**從入口頁點連結進入頁面**（不是直接開網址），然後：

- 按主題切換鈕，確認真的會換色（曾經因為只綁 `DOMContentLoaded` 而在 Turbo 換頁後失效）
- 送出篩選表單，確認 turbo frame 有更新、載入中狀態有出現又消失
- 點麵包屑「入口頁」，確認是整頁導覽而不是顯示 "Content missing"

### 5. 空狀態與錯誤狀態

篩出一個不會有資料的組合（例如選一個專案 ×「已逾期」×某個沒資料的年度），確認顯示的是
「目前無符合條件的任務」這類空狀態，而不是空白區塊或壞掉的表格。

## 怎麼跑

1. 開一個分頁，逐頁 `navigate`，每頁等內容載完再截圖（頁面要打 Google API，別太早截）
2. 每頁在三種寬度各截一張，需要時再切深色主題補截
3. 量測類的檢查用 `javascript_tool` 跑一小段 script 取座標／寬度，不要憑截圖目測
4. 順手看一下 console 有沒有 error（`read_console_messages`）
5. 截圖存到 scratchpad 目錄，不要留在專案裡

## 回報格式

只列出真的有問題的項目，沒問題的類別直接略過。每一項都要讓人能自己重現：

```markdown
## 視覺 QA 結果

### /dashboard —— 桌機 1440

- **問題**：AMAS System 與 RAG 兩個區塊的「類型」欄起始位置差 37px
  **重現**：開 /dashboard，比較兩個專案表格第二欄的左邊界
  **原因**：每個專案是獨立 table，未指定欄寬時各自依內容計算
  **建議**：`.project-tasks` 加 `table-layout: fixed` 並明訂各欄寬度

### /issues —— 手機 390

- **問題**：...
```

最後補一句總結：檢查了哪幾頁、哪幾種寬度、有沒有截到 console error。如果全部都正常，就說
「檢查了 X 頁 × Y 種寬度，未發現問題」，並附上截圖路徑讓使用者自己也能看。

## 已知的歷史問題（迴歸清單）

這幾個是真的發生過的，改動相關區域後值得特別確認一次：

- 主題切換鈕在 Turbo 換頁後失效（只綁 `DOMContentLoaded`）
- 305 表格欄位跨專案區塊對不齊（獨立 table + 自動欄寬）
- 長任務名稱把「類型」「日期」等短欄位擠到直向斷行
- fieldset 的 `<legend>` 佔掉獨立一行，讓篩選列的控制項高度對不齊
- 篩選送出太快時，載入中狀態只閃一下，看起來像畫面故障
